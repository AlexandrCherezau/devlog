# Eldheim devlog

Сбор фактических изменений от Codex и публикация дельт для сборщика патчноутов.
Источник — отдельные JSON-записи в `entries/` на `main`; человек читает готовые
Markdown-файлы в [ветке updates](https://github.com/Eldheim/devlog/tree/updates).
Старый ручной `devlog.md` также поддерживается.

## Устройство

1. После завершения задачи Codex по инструкции AGENTS.md вызывает skill
   `eldheim-devlog`: компонент, изменения, реальная проверка, состояние деплоя
   и известные ограничения.
2. Коллектор сохраняет запись в локальную очередь и пытается отправить её через
   GitHub API. Рабочие каталоги игровых проектов не коммитятся. Каждая задача
   получает отдельный неизменяемый файл; параллельные агенты не перетирают общий журнал.
3. GitHub Actions обрабатывает ещё не опубликованные изменения по порядку,
   включая несколько коммитов за один пуш. Markdown складывается в ветку
   `updates`, где хранится и пройденная позиция.
4. При недоступности GitHub запись остаётся в очереди. Пользовательский таймер
   повторяет отправку раз в пять минут. Повторная доставка сверяет содержимое.

Skill и AGENTS.md требуют от агента подготовить фактическую запись. Это не сканер
переписок: произвольный агент, который не загрузил инструкции или проигнорировал
их, может пропустить запись. Доставка уже созданной записи восстанавливается
автоматически после сетевых ошибок.

## Установка для Eldheim

Нужны **Python3.11+**, Git, GitHub CLI и права записи в целевой репозиторий:

```bash
gh auth status
git clone https://github.com/Eldheim/devlog.git
cd devlog
python3 scripts/install_codex.py \
  --repository Eldheim/devlog \
  --project-root /абсолютный/путь/к/eldheim
```

Установщик копирует skill в `~/.agents/skills/eldheim-devlog`, добавляет алиас в
`$CODEX_HOME/skills`, сохраняет настройки в `~/.config/eldheim-devlog/config.json`
и добавляет ограниченный блок в глобальный и проектный AGENTS.md. Существующие
инструкции, авторизация и история Codex сохраняются. На Linux с systemd включается
таймер; для другого планировщика есть `--no-timer`.

Начни новую сессию Codex, чтобы инструкции загрузились. Явный вызов:
`$eldheim-devlog`. После обновления исходников повтори ту же команду установки.

Для своей машины или сервера: **[инструкция развёртывания](docs/SETUP_RU.md)**.

## Добавить запись

Запускай из настроенного каталога проекта или его подкаталогов:

```bash
python3 ~/.agents/skills/eldheim-devlog/scripts/record_update.py add \
  --project guild --title 'Кланы используют общий уровень' \
  --change 'Проверки создания и вступления читают общий уровень персонажа' \
  --status deployed-prod \
  --verification 'Показатели сверены с API у подключённых игроков'
```

Опции `--change`, `--verification`, `--note` можно повторять.

| Статус | Что произошло |
| --- | --- |
| `implemented` | Изменения внесены, значимые проверки ещё не пройдены |
| `tested` | Проверки пройдены, деплоя ещё нет |
| `deployed-test` | Установлено и проверено на тестовом сервере |
| `deployed-prod` | Установлено и проверено на основном сервере |

Компиляция не равна игровой проверке. Если нужна ручная проверка, укажи это
через `--note`. Не публикуй переписки, сырые логи, секреты, локальные пути,
IP-адреса и персональные данные. Фильтр ловит распространённые секреты и приватные
пути, но не заменяет просмотр текста самим агентом.

`--dry-run` показывает запись без сохранения и отправки. `--queue-only`
сохраняет её для таймера. Одинаковые факты повторно не публикуются; новый деплой
оформляется своей записью. Не используй один `--id` для разных фактов.

## Обслуживание

```bash
python3 ~/.agents/skills/eldheim-devlog/scripts/record_update.py status
python3 ~/.agents/skills/eldheim-devlog/scripts/record_update.py flush
systemctl --user status eldheim-devlog-publish.timer
journalctl --user -u eldheim-devlog-publish.service -n 20 --no-pager
gh run list --repo Eldheim/devlog --workflow devlog-updates.yml
gh workflow run devlog-updates.yml --repo Eldheim/devlog
```

`Published` означает, что JSON доставлен на `main`; Markdown появляется после
успешного Actions-запуска. `Queued` без `Published` означает ожидание доставки
на этой машине. Для исправления фактов добавляй новую запись, не переписывай
опубликованный JSON. GitHub-обработку можно повторить вручную; также настроен
ежедневный восстановительный запуск.

## Разработка

```bash
python3 -m unittest discover -s tests -v
python3 -m compileall -q scripts tests
```

Тесты используют временные локальные Git-репозитории и подставной API; в GitHub
они не публикуют, реальные игровые данные не меняют. Зависимостей pip нет.
