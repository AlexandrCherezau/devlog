# Развёртывание своего девлога с Codex

Codex оставляет записи о фактических изменениях проекта. GitHub Actions собирает
из них Markdown-дельты в ветке `updates` для сборщика патчноутов. Telegram-токен
и отдельный VPS не нужны. Агент составляет короткую проверяемую сводку задачи,
с указанием реальной проверки и места установки изменений.

## 1. Создать свой репозиторий

Нужны Git, Python **3.11+** и GitHub CLI. Войди в свой GitHub и создай форк:

На Windows используй WSL2 с Ubuntu: Git, Python, `gh` и сам Codex запускаются
внутри одного WSL-окружения. Установка в native Windows не поддерживается.

```bash
gh auth login
gh repo fork Eldheim/devlog --clone
cd devlog
```

Для своего сервера настрой именно свой `ТВОЙ_ЛОГИН/devlog`. Доступ к Eldheim
и чужие токены не нужны. Можно перенести файлы в отдельный репозиторий;
его основная ветка должна называться `main`.

В GitHub открой **Actions** и включи workflows в форке, если предлагается их
активировать. В **Settings → Actions → General** выполнение должно быть разрешено.
Публикационный workflow уже запрашивает `contents: write`; ограничения организации
должны разрешать запись в этот репозиторий.

## 2. Установить skill и инструкции

Из скачанного каталога `devlog`:

```bash
python3 scripts/install_codex.py \
  --repository ТВОЙ_ЛОГИН/devlog \
  --project-root /абсолютный/путь/к/проекту
```

Указывай каталог проекта, а не весь домашний каталог. Установщик создаёт:

- skill `~/.agents/skills/eldheim-devlog` и алиас в `$CODEX_HOME/skills`;
- блок в глобальном и проектном AGENTS.md, ограниченный этим проектом;
- настройки `~/.config/eldheim-devlog/config.json` и локальную очередь;
- на Linux с systemd — пользовательский таймер повторной отправки раз в5минут.

Существующие инструкции сохраняются. Авторизация и история Codex не меняются.
Если используется особый `$CODEX_HOME`, запускай установщик с тем же окружением,
с которым запускается Codex. Каждый разработчик входит в GitHub сам через
`gh auth login` и использует свои права записи в целевой репозиторий.

Для macOS или Linux без systemd добавь `--no-timer`. Немедленная отправка
сохранится; в своём планировщике запускай каждые5минут:

```bash
python3 ~/.agents/skills/eldheim-devlog/scripts/record_update.py flush
```

Начни **новую сессию Codex**, чтобы установленные инструкции загрузились.
Навык можно вызвать явно: `$eldheim-devlog`. Другие агенты тоже могут следовать
проектному AGENTS.md, если они его читают. Это не сканер переписок и не гарантия,
что произвольный агент без этих инструкций составит запись.

## 3. Проверить на реальной задаче

После небольшого настоящего изменения запусти из своего проекта:

```bash
python3 ~/.agents/skills/eldheim-devlog/scripts/record_update.py add \
  --project server \
  --title 'Краткое название реального изменения' \
  --change 'Что теперь работает иначе' \
  --status tested \
  --verification 'Какая проверка действительно выполнена' \
  --dry-run
```

Просмотри запись и повтори без `--dry-run`. `Published` со ссылкой означает,
что JSON появился на `main` в `entries/`. `Queued` означает, что он пока сохранён
только локально. Затем открой последний Actions-запуск и ветку `updates`:
там должен появиться Markdown с этим изменением.

Если запусков нет, открой **Actions → Publish devlog updates → Run workflow**.
Или выполни:

```bash
gh workflow run devlog-updates.yml --repo ТВОЙ_ЛОГИН/devlog
```

## 4. Состояния и факты

| Статус | Что действительно произошло |
| --- | --- |
| `implemented` | Код или конфиг изменён; проверки ещё не пройдены |
| `tested` | Проверки пройдены; на сервер ещё не установлено |
| `deployed-test` | Установлено и проверено на тестовом сервере |
| `deployed-prod` | Установлено и проверено на основном сервере |

Опции `--change`, `--verification`, `--note` можно повторять. Компиляция,
игровая проверка и деплой — разные факты. Оставшуюся клиентскую проверку
указывай через `--note`. Не публикуй переписки, сырые логи, секреты, IP-адреса,
локальные пути, персональные данные и идентификаторы игроков.

## 5. Повседневная работа и обслуживание

После существенной завершённой задачи Codex добавляет отдельную запись.
Параллельные агенты не перетирают общий журнал. Если сети нет, запись остаётся
в очереди; таймер повторяет доставку. Повторные отправки сверяют содержимое
и не переписывают существующий JSON. Исправление оформляется новой записью.
Человек, который собирает патчноуты, читает ветку `updates`.

```bash
python3 ~/.agents/skills/eldheim-devlog/scripts/record_update.py status
python3 ~/.agents/skills/eldheim-devlog/scripts/record_update.py flush
systemctl --user list-timers eldheim-devlog-publish.timer
journalctl --user -u eldheim-devlog-publish.service -n 20 --no-pager
gh run list --repo ТВОЙ_ЛОГИН/devlog --workflow devlog-updates.yml
```

Таймер работает, пока запущен пользовательский systemd manager. На выключенном
ПК доставки нет; она возобновится после запуска/входа. GitHub-обработка уже
доставленных записей от ПК не зависит.

Чтобы обновить установленную версию:

```bash
git pull --ff-only
python3 scripts/install_codex.py \
  --repository ТВОЙ_ЛОГИН/devlog \
  --project-root /абсолютный/путь/к/проекту
```

Установка skill и AGENTS.md соответствует
[официальной документации Codex](https://learn.chatgpt.com/docs/customization/overview#skills).
